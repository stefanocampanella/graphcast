At the start of the week, training jobs on JUPITER failed one after the other (multi-node meshes, loss dtype, missing coordinates), and once they ran, the model skipped its message passing.
Today a training step takes 0.48–0.51 s on 1 to 8 nodes, compute bound (GPUs 94 % busy on 1 node), and throughput scales nearly linearly.

  • Only zarr v2 with 8 Grain workers × 2 threads keeps the GPUs fed; every other format or loader setting leaves them waiting for data.
  • XLA/JAX tuning flags make no difference; disabling InfiniBand costs 7–8 % on 2 nodes.
  • 16 message passing steps (original GraphCast) cost ~23 % more than 8 on the coarse mesh.
  • Larger meshes: with the processor in a scan, meshes up to 50 km (5.2× the coarse mesh nodes) fit with 16 steps at all 50 levels, 30 km with edge chunks; the fine mesh still does not.
  • Mesh size and loss: finer meshes lower the loss of temperature, salinity and currents and raise that of sea surface height (demo stack).
  • 50 levels: at most 2 Grain workers fit in host memory, so training is loader bound.

For reference: original GraphCast ≈ 7.70 s/step (32 TPU v4); our Leonardo PoC ≈ 2.0 s/step on 8 nodes (different configuration).

    return Mesh(devices, axis_names,
                axis_types=(AxisType.Explicit,) * len(axis_names))

  def make_batch_mesh() -> Mesh:
    return _make_hybrid_mesh(("batch",),

↓ more: Why offloading did nothing · An XLA bug

Why offloading did nothing

  • Remat (jax.checkpoint) drops a block's activations in the forward pass and recomputes them in the backward pass; its policy saves or offloads named values instead.
  • The names marked the outputs of the rematerialized blocks. A block's output is not one of its own residuals: it is the input of the next block, kept by the code around the blocks, where no policy applies.
  • Compiled program: 0 host buffers, with or without the policy. Every "with/without offloading" result of 22 Oct measured the same thing.
  • Fix: the same policy also around the whole loss (policy.remat_loss).

  # every block of the processor, as before
  graph = checkpoint_name(graph, "message_passing")
  block = hk.remat(block, policy=policy)

  # new: policy.remat_loss, a checkpoint around the loss,
  # where the block outputs are intermediates
  local_loss_fn = jax.checkpoint(loss_fn.apply, policy=policy)
  

  names on block outputs         host buffers S(5): 0
  ... with an outer checkpoint   host buffers S(5): 5

Full model, now: the GPU needs 5–9 GiB less (about 10 %) for 8–87 GiB of host memory; same losses. The GPU peak is recomputing a block, not the saved activations.

Offloading costs ~20 % more compute per step and fills host memory: off by default.

An XLA bug: offloading inside a switch in a scan


  INTERNAL: during context [end-of-post-layout_assignment]:
    Expected instruction to have shape equal to
    (s32[], bf16[200000,256]{1,0}, bf16[8,200000,256 ...
  • The scanned processor picked each step's network with hk.switch; XLA cannot compile host offloading inside a switch in a scan.
  • Same in NVIDIA JAX 26.06 (JAX 0.10.1), 26.09 (0.11.1) and the 2026-10-24 nightly (0.12.1.dev); a scan over stacked parameters compiles in all three.

  # DeepTypedGraphNet: one pure step, per-step parameters
  # (the same with and without scan), scanned stacked
  step = hk.transform(step_fn)
  params = [hk.lift(step.init, name=f"processor_step_{i}")(
              hk.maybe_next_rng_key(), features)
            for i in range(num_steps)]
  stacked = tree_map(lambda *p: jnp.stack(p), *params)
  features, _ = jax.lax.scan(
    lambda f, p: (step.apply(p, None, f), None), features, stacked)
A first version (a layer stack) also stacked the unrolled networks and the 1-step encoder and decoder: 35 % slower steps (0.63 instead of 0.46 s), visible only once a run was compute bound. Fixed; the final run and the demo were repeated. Now scan and unrolled share one parameter tree.

Lessons and next steps

Lessons

  • Check the model computes: step time that ignores model size is a red flag.
  • Verify what reaches the container: environment variables, flags, CPUs.
  • Measure all ranks: one rank's stall looks like everyone's compute.
  • Benchmarks interfere on a shared file system.
  • Check that a memory optimization does something: offloading named only block outputs, and offloaded nothing.
  • Time changes where compute dominates: a loader-bound memory sweep hid a 35 % slowdown.
  • Mesh size is not free: finer meshes help local fields and hurt sea surface height at fixed depth.

Next steps

  • Reduce host memory of the training process (480 GB per node) to fit more loader workers at 50 levels.
  • Fit the fine mesh (84–112 GiB per GPU): shard the graph over the 4 GPUs of a node.
  • Mesh size: more message passing steps on fine meshes, several seeds, validation loss.
  • Report the XLA bug (switch in a scan with host offloading) with the reproducer.
  • Full training run (40 000 steps) and rollouts.
  • Data on node-local or faster storage to isolate jobs from each other.
